## 1. Концепция и философия

**Что это за игра**

AI Life Simulator — веб-приложение которое объединяет симулятор жизни, интерактивную книгу, визуальную новеллу без визуала и RPG с прокачкой. Игра порождает живые нарративы через комбинацию процедурного движка, психологической симуляции персонажей и ИИ для ключевых моментов.

**Базовые принципы**

Движок локальный, ИИ вызывается только для того что он делает хорошо. Симуляция, память, время, карта, статы — всё живёт на компьютере игрока. ИИ пишет тексты важных сцен и рефлексии. Всё остальное работает без интернета.

Игра не про победу, а про проживание. Нет цели "дойти до конца". Есть персонаж, мир, жизнь, истории которые получаются. Эмерджентный нарратив как в Dwarf Fortress и RimWorld, но с человеческой эмоциональной глубиной через ИИ.

Игрок одновременно демиург, наблюдатель и соавтор. Он создаёт мир и персонажей, задаёт ключевые события, но не контролирует каждый шаг. Персонажи живут сами, и в этом драма.

**Целевой опыт**

Человек заходит в игру, создаёт мир, создаёт персонажа, начинает жить. Через час он уже привязан. Через десять часов он плачет над смертью NPC которого никто не писал. Через сто часов у него есть собственная эпопея на несколько поколений которую он будет пересказывать друзьям.

## 2. Режимы игры

**Режим Книга**

История идёт главами. Игрок не принимает микро-решений, а задаёт направление и читает как всё разворачивается. Главы генерируются по сюжетным якорям, процедурным событиям и естественному ходу жизни. Текст атмосферный, литературный, от третьего лица или от первого в зависимости от настроек.

Темп задаётся игроком. Можно попросить главу про конкретный день, конкретное событие, конкретные отношения. Можно попросить перемотку "что было за последние три года в двух главах". Можно попросить написать главу глазами другого персонажа.

**Режим Игра (VN без визуала)**

Диалоги, сцены, варианты ответов. Игрок непосредственно ведёт ГГ через мир. Каждая сцена — это выход в локацию, взаимодействие с NPC, реплики с выбором, последствия. Ближе к Disco Elysium или Sunless Sea по ощущению.

В этом режиме активно работает система статов и навыков — проверки Харизмы при убеждении, Интеллекта при изучении, Восприятия при поиске. Процедурный движок заполняет рутину, ИИ пишет ключевые моменты.

**Режим Наблюдателя**

Медитативный режим где игрок вообще не вмешивается. Персонаж живёт сам, движок принимает решения на основе его черт и настроения, ИИ или процедура описывают что происходит. Игрок просто читает. Можно поставить на паузу и вмешаться в любой момент.

**Режим Хроники**

Гибридный режим для оффлайна или экономии токенов. Игра идёт, события накапливаются в структурированный лог. Когда появляется возможность — игрок нажимает "напиши главу" и ИИ превращает лог в полноценный нарратив. Можно играть на телефоне в поезде, а вечером получить красивую главу.

**Переключение режимов**

Между режимами можно переключаться в любой момент. Игра сама подсказывает когда какой режим лучше — тихая повседневность в хронике, кульминации в книге, активные взаимодействия в игре.

## 3. Технический стек

**Frontend**

React с TypeScript как основа. Сборка через Vite. Один SPA со всеми вкладками, редакторами, читалкой. Tailwind для стилей. Zustand для глобального стейта. Компонентная структура где каждая вкладка — отдельный модуль.

**Локальное хранение**

IndexedDB для основных данных — миров, персонажей, истории, сохранений. Достаточно ёмкий, работает везде в браузерах. LocalStorage для настроек и быстрого кэша. Возможность экспорта/импорта миров в JSON-файл для бекапов.

**ИИ**

Anthropic API (Claude) как основной провайдер. Опционально поддержка других — OpenAI, локальные модели через Ollama. Ключ API хранится локально, никакого бэкенда у нас.

**Архитектура приложения**

Ядро движка полностью отделено от UI. Это чистый TypeScript-модуль с классами и функциями без зависимостей от React. UI только подписывается на состояние через Zustand. Это значит движок можно потом портировать куда угодно — в Electron, в мобильное приложение, в серверную версию.

**Тестирование**

Vitest для юнит-тестов движка (критично для симуляции и процедурной генерации). Тесты пишутся вместе с реализацией каждого этапа.

**Формат данных**

Всё JSON. Человекочитаемо, легко бекапить, легко редактировать вручную, легко делиться. Версионирование схемы данных с миграциями.

**Offline-first**

Service Worker для кэширования приложения. После первой загрузки работает без интернета. ИИ требует интернета только для своих вызовов, остальное всё локально.

## 4. Архитектура данных

**World (Мир)**

Корневая сущность. Содержит настройки генерации, правила, жанр, временную шкалу, карту, глобальное состояние. Все остальные сущности принадлежат миру.

```
World {
  id, name, created_at
  schemaVersion: number
  settings: WorldSettings
  map: Map
  timeline: Timeline
  globalState: GlobalState
  characters: Character[]
  locations: Location[]
  factions: Faction[]
  storyAnchors: StoryAnchor[]
  events: Event[]
  rumors: Rumor[]
}
```

**Character (Персонаж)**

Самая большая и важная сущность. Всё что касается персонажа — тут.

```
Character {
  // Идентичность
  id, name, aliases, previousNames
  species: human | furry | elf | custom
  appearance: описание, возрастные стадии
  
  // Биография
  birthDate, deathDate?
  birthplace, nationality, culture
  biography: текст
  ancestry: генеалогическое дерево
  
  // Личность
  traits: Trait[]  // черты с модификаторами
  values: Value[]  // что ему важно
  fears, dreams, secrets
  worldview: динамически формируется
  
  // Статы и навыки
  stats: { intelligence, charisma, will, ... }
  skills: Skill[]  // включая процедурные
  hiddenStats?: { magic_level, ... }
  
  // Психология
  mood: number (0-100)
  moodTarget: number
  thoughts: Thought[]  // активные мудлеты
  needs: Needs  // голод, сон, социальная нужда и т.д.
  mentalBreakThreshold: number
  
  // Отношения
  relationships: Map<characterId, Relationship>
  // Relationship содержит trust, attraction, respect, 
  // fear, envy — многомерность
  
  // Память
  memory: {
    hot: Event[]    // последние сцены
    warm: Summary[] // недавние месяцы
    cold: Summary[] // давнее прошлое
  }
  reflections: Reflection[]  // синтезированные выводы
  
  // Жизнь и предыстория
  previousLife?: PreviousLife  // для реинкарнации
  memoryLocked?: { until: Date, content: Memory }
  
  // Состояние
  currentLocation: locationId
  schedule: Schedule
  activeGoals: Goal[]
  currentActivity: Activity
  
  // Метаигровое
  role: playerCharacter | majorNPC | backgroundNPC
  simulationLevel: hot | warm | cold
}
```

**Location (Локация)**

```
Location {
  id, name, type (city | village | dungeon | room | ...)
  coordinates: {x, y} | {lat, lng}
  area: polygon
  parent: locationId  // район в городе, город в стране
  children: locationId[]
  
  atmosphere: { beauty, safety, prosperity, ... }
  currentOccupants: characterId[]
  
  history: Event[]  // что тут происходило
  description: текст
  procedural: { pools, templates }  // для процедурных описаний
}
```

**Event (Событие)**

```
Event {
  id, timestamp
  type: personal | social | world | anchor
  scaffold: EventScaffold  // шаблон события
  participants: characterId[]
  location: locationId
  description: текст  // процедурный или от ИИ
  consequences: StateChange[]
  witnesses: characterId[]
  narrativeWeight: number  // важность для истории
}
```

**Relationship (Отношение)**

```
Relationship {
  from: characterId, to: characterId
  trust: -100 to 100
  attraction: -100 to 100
  respect: -100 to 100
  fear: -100 to 100
  envy: -100 to 100
  
  status: stranger | acquaintance | friend | 
          romantic | family | rival | enemy
  
  history: Interaction[]
  sharedEvents: eventId[]
  significantMoments: Moment[]
}
```

**StoryAnchor (Сюжетный якорь)**

```
StoryAnchor {
  id, title, description
  timing: absolute | relative | conditional
  target?: timestamp | age | condition
  participants: characterId[]
  importance: low | medium | high | critical
  status: pending | active | completed | skipped
  prerequisites: Condition[]
  tags: string[]
}
```

## 5. Системы мира

**Временная шкала**

Движок тикает. Размер тика настраивается — минута, час, день, неделя. Быстрая перемотка проскакивает тики пачками без детальной симуляции. Детальная симуляция включается когда игрок в режиме игры или когда важное событие.

События имеют временные метки. История мира — это отсортированный список событий которые игрок может просматривать, фильтровать, зуммировать.

**Система нужд**

У каждого активного персонажа вектор нужд. Физические (здоровье, голод, сон, безопасность), социальные (общение, принадлежность, близость), психические (смысл, самооценка, стабильность), амбициозные (прогресс, статус, творчество).

Нужды деградируют со временем. Когда падают ниже порога — генерируется мысль (в смысле RimWorld Thought) которая влияет на настроение. Если критично — триггерится событие (заболел, сорвался, убежал).

**Система настроения**

0-100 шкала. Есть Target (рассчитывается мгновенно из суммы активных мыслей и черт) и actual (подтягивается к Target с инерцией). Черты характера сдвигают базовый уровень и пороги срыва.

Ниже 35 — риск малого срыва, 20 — серьёзного, 5 — экстремального. Срыв это событие которое триггерит сцену от ИИ или процедуры. После срыва — катарсис, +40 к настроению на несколько дней.

**Система событий**

Три источника:

Якорные — от игрока, запланированные. Движок ждёт условий и триггерит.

Процедурные — из правил. Возраст 6-7 → начало учёбы. Отношения > 80 → углубление. Настроение < 20 → срыв.

Мировые — глобальные. Войны, эпидемии, экономика, политика. Бросаются по расписанию.

Событие имеет "скаффолд" — шаблон с условиями, участниками, ожидаемыми последствиями. ИИ или процедура заполняют скаффолд деталями.

**Система слухов**

Каждое заметное событие порождает слух. Свидетели запоминают исходную версию. При разговорах передают другим, каждая передача искажает. Через время по городу гуляют легенды. Персонажи могут иметь разную "информационную картину мира".

**Мета-нужды мира**

По аналогии с Sims-городом. Движок следит за балансом населения, занятости, профессий, полов. Если нарушается — подталкивает события. Родился мальчик вместо девочки если гендерный баланс нарушен. Случайный NPC получает работу если безработица высокая. Это дешёвле чем симулировать всех.

**Погода и сезоны**

Отдельная подсистема. Климат локации + сезон + случайность. Влияет на настроение всех в локации. Автоматически модифицирует процедурные описания ("зимой", "в дождь"). Редкие экстремальные явления — события.

## 6. Системы персонажей

**Редактор персонажа**

Большая форма со всеми полями. Базовые — имя, возраст, вид, внешность. Личность — черты из списка или кастомные, ценности, страхи, мечты. Биография — свободное текстовое поле + структурированные события. Статы — начальное распределение очков. Навыки — выбор стартовых. Отношения — связи с другими персонажами в мире. Специальное — скрытые силы, флаги памяти, роль в сюжете.

Режимы создания: с нуля, по шаблону (архетип), случайный, сгенерировать ИИ по описанию.

**Черты (Traits)**

Библиотека базовых черт на старте — 50-100 штук. Каждая имеет описание, модификаторы, триггеры, противоречия. Черты можно создавать свои с указанием механики.

Примеры: Гордый (+5 к Воле, -штраф настроения при унижении, особые реакции), Травмированный (случайные флешбеки, триггер страха в похожих ситуациях), Эмпат (+бонус к Харизме, обратное ощущение эмоций других).

**Статы**

Базовых 6-8. Интеллект, Харизма, Воля, Восприятие, Ловкость, Выносливость, Креативность. Опционально — Удача.

Диапазон 1-20 или 0-100, выберу при реализации. Модифицируются чертами, временными состояниями, возрастом (старость — снижение физических, рост мудрости).

**Навыки**

Конкретные умения. Встроенная библиотека — Математика, Медицина, Переговоры, Бой, Готовка, и т.д., несколько десятков. Каждый привязан к стату-родителю. Уровень 0-100. Используется в проверках механики и как контекст для ИИ.

**Процедурные навыки**

Движок отслеживает действия ГГ. Когда паттерн повторяется (N раз за M времени) — открывает навык автоматически. Базовые правила паттернов прописаны. Игрок видит уведомление "Открыт новый навык".

**Кастомные навыки**

Игрок создаёт через специальный интерфейс. Указывает название, описание, родительский стат, механику (что проверяет, какие бонусы). Навык должен быть применён N раз чтобы закрепиться. Это предотвращает манчкинство.

**Система прогрессии**

Короткие петли — использовал навык, получил опыт, видимый прогресс. Средние — открыл новую способность, новая возможность применения. Длинные — достиг мастерства, изменились отношения мира. Сверхдлинные — персонаж стал кем-то значимым в мире.

Параллельные шкалы — деньги, репутация, статус, связи, известность, сила, влияние.

**Награды от игрока**

Отдельная кнопка — выдать/отнять. Открывается диалог: что даём (стат, навык, черта, предмет, репутация), кому, за что (записывается в историю персонажа), сколько. Движок применяет мгновенно, событие логируется.

**Голос Системы**

Для персонажей у которых есть Система (как Альтер) — отдельный подперсонаж с характером. В редакторе задаётся: тон (холодный, ироничный, заботливый), формальность, отношение к ГГ. Банк реплик Системы генерируется автоматически по этим параметрам.

Система может уведомлять о событиях, давать советы, спорить с ГГ, описывать статы, предлагать задания. Работает полностью без ИИ, но ИИ может писать её реплики красивее если включён.

**Банки реакций (живость без ИИ)**

Для каждой черты — банк типичных реакций. Структура:

```
Reaction {
  trigger: тип события
  emotion: эмоция
  template: текст с слотами
  conditions: когда применять
}
```

Когда событие происходит, движок выбирает подходящие черты, эмоции, и собирает реакцию из шаблонов с подстановкой контекста.

Для нечеловеческих видов (барсы, фурри) — отдельные банки с видовыми реакциями (прижимание ушей, шерсть дыбом, урчание).

## 7. Процедурная генерация

**Движок шаблонов**

Парсер строк с слотами типа `#имя_слота#`. Слоты раскрываются рекурсивно из пулов. Поддержка условий, модификаторов, тональностей.

```
"#время_суток# #герой# #действие# в #локация#. 
 #атмосферная_деталь#."
```

**База пулов**

Три уровня пулов:

Базовый общий — универсальные слоты, работают в любом мире (утро, вечер, еда, эмоции, погода). 2000+ вариантов, пишется один раз вручную.

Жанровые — фэнтези, sci-fi, современность, постапокалипсис. По 500-1000 на жанр.

Генерируемые под мир — ИИ вызывается один раз при создании мира. Задача: "для мира X создай 50 описаний погоды, 50 местных блюд, 50 типичных фраз, 50 названий улиц". Один вызов — тысячи уникальных элементов на всю игру.

**Контекстная осведомлённость**

Пулы имеют метки. Время суток, сезон, настроение, локация, культура. Движок выбирает подходящий вариант по контексту. Не будет "подснежники зимой".

**Тональности**

Один смысл — разные тона. Мрачный, тёплый, нейтральный, ироничный, торжественный. Движок выбирает тональность по контексту сцены.

**Склонение русского**

Интеграция JS-библиотеки для морфологии (например, `az` или `russian-inflection`). У каждого персонажа хранится грамматический профиль (род, падежи имени). Шаблоны подставляют правильные формы.

**Анти-повтор**

Движок ведёт список недавно использованных вариантов. Снижает им вес при выборе. Через N использований "забывает" и снова разрешает.

**Процедурные генерации**

Описания локаций, бытовые события, сплетни, слухи, реакции NPC, внешность второстепенных персонажей, названия мест, имена детей NPC, атмосферные переходы, сны, газетные заголовки, письма, обрывки разговоров.

**Гибридный режим**

В главе ИИ пишет ключевые сцены, процедура — переходы между ними. Это снижает расход токенов в 2-3 раза при сохранении качества.

## 8. ИИ-интеграция

**Менеджер контекста**

Самый важный модуль. Собирает пакет для каждого вызова ИИ.

Состав пакета: описание мира (сжато), профили активных персонажей (только нужные поля), релевантные воспоминания (через поиск по тегам), последние 3-5 событий, текущая локация, целевой скаффолд события, инструкция по стилю, ограничения (длина, темп, конец сцены).

Размер пакета оптимизируется. Для простой сцены — 2000 токенов контекста. Для важной — до 8000. Для главы книги — до 20000.

**Стратегии памяти**

Горячая память — последние сцены как есть.

Тёплая — последние месяц-год в виде сжатых описаний по 1-2 предложения на событие.

Холодная — всё давнее в виде рефлексий (синтезированные паттерны), ключевые вехи жизни.

После каждой важной сцены ИИ возвращает не только текст, но и рефлексию — что изменилось в персонажах, какие новые паттерны заметны. Это и есть механизм архивации.

**Форматированный вывод**

Запросы к ИИ структурированы. Не "напиши сцену", а конкретный формат ответа:

```
{
  "narrative": "сам текст сцены",
  "dialogue": [...],
  "mood_changes": [...],
  "relationship_changes": [...],
  "new_memories": [...],
  "reflection": "что этот момент значит",
  "should_trigger_next": { ... }
}
```

Это даёт машиночитаемый апдейт стейта + человекочитаемый текст.

**Контроль темпа**

Промпт явно указывает: "сцена покрывает ~X времени", "должна закончиться тем-то", "не больше Y слов", "N битов диалога". Это убирает "вечные вечера".

**Чанкование диалогов**

Длинные диалоги пишутся частями. Один обмен — одна генерация. Игрок видит → жмёт дальше → следующий обмен с учётом предыдущего. Это даёт ощущение живого разговора и возможность выйти.

**Режимные промпты**

Для каждого режима (книга, игра, наблюдатель, хроника) — свой набор промптов. Разный стиль, разный формат, разные ограничения.

**Библиотека промптов**

Все промпты хранятся как шаблоны в коде. Версионируются. Каждый имеет цель, ожидаемый вывод, примеры. Это облегчает итерацию — можно менять один промпт не трогая движок.

**Несколько провайдеров**

Абстракция LLMProvider. Claude, GPT, Gemini, локальные — одинаковый интерфейс. Игрок выбирает в настройках. Ключи хранятся локально зашифрованными.

**Рекомендуемые модели Claude**

- `claude-opus-4` — ключевые главы пролога, важные эмоциональные сцены, максимальное качество
- `claude-sonnet-4-5` — основная рабочая лошадка, баланс качества и цены для большинства сцен
- `claude-haiku-4-5` — процедурные мелочи, рефлексии, быстрые реакции NPC

По умолчанию предлагать Sonnet. Давать пользователю выбор в настройках.

**Расход токенов**

Показатель расхода в интерфейсе. Игрок видит сколько уходит на что. Лимиты — можно выставить "не больше X токенов в день". Автопереключение на процедурный режим при достижении лимита.

## 9. Карта и пространство

**Векторная карта**

Многослойная. Ландшафт (полигоны биомов), политика (границы стран), поселения (точки с данными), связи (дороги как граф), локальные планы (улицы городов которые игрок посетил).

Рендеринг через SVG или Canvas. Не нужна красота на старте — нужна функциональность. Можно зуммировать от континента до комнаты.

**Процедурная генерация мира**

Послойная как в Dwarf Fortress. Высоты → климат → биомы → реки → поселения → связи → история. Каждый слой детерминистский, воспроизводимый по сиду.

Настройки — размер, плотность, жанр, эпоха. Игрок может отредактировать вручную после генерации.

**Опция реальной карты**

Продвинутая функция. Интеграция упрощённых данных OpenStreetMap. Выбор региона, масштаба, эпохи. Игрок может потом править. На старте — не делаем, добавляем позже.

**Позиционирование**

У каждого активного NPC — координаты + расписание. Тик — обновление позиций по путям.

**Радиусы восприятия**

Каждый персонаж имеет радиус зрения (зависит от локации — в здании меньше, на равнине больше) и радиус слуха. Препятствия учитываются (стены блокируют видимость, приглушают звук).

Это база для многих эмерджентных фич: кто видел что, кто слышал разговор, секретные встречи, случайные пересечения.

**Движение без телепорта**

Персонажи физически идут по путям на карте. Время в пути учитывается. Встреча двух персонажей — это момент когда их пути пересекаются в одной точке с условиями для контакта.

**Пре-симуляция истории**

При создании мира — симуляция предыдущих N лет для наполнения истории. По уровням LOD: статистика стран, крупные события, важные фигуры, предки ГГ (5 поколений детально). Занимает несколько секунд при создании.

Если мир похож на реальный — импорт исторических событий из заранее подготовленной базы.

**Локальные планы**

Города, здания, интерьеры — открываются когда ГГ туда попадает. До первого визита — только ярлык на карте. После — детальный план, сохраняется.

## 10. Интерфейс и вкладки

**Главный экран**

Центральное окно — текущая сцена или глава. Сбоку — быстрый статус ГГ (настроение, здоровье, активные мысли). Внизу — строка управления (режим, время, действия). Вверху — навигация по вкладкам.

**Вкладка Мир**

Карта. Зуммирование. Переключение слоёв (политика, климат, дороги, путешествия ГГ). Клик по месту — информация, история, известные NPC. Временной слайдер — как выглядел мир в разные годы.

**Вкладка Персонажи**

Список всех персонажей с фильтрами (живые, мёртвые, семья ГГ, друзья, враги). Клик — профиль. Редактор для тех кого можно редактировать (ГГ и им созданные). Просмотр для NPC. Генеалогическое дерево как отдельный вид.

**Вкладка Отношения**

Граф отношений ГГ. Визуализация связей. Клик по связи — история взаимодействий с этим персонажем, все совместные события, текущие измерения отношений.

**Вкладка Сюжет**

Список сюжетных якорей. Статусы (ожидает, активен, выполнен). Можно добавить новый якорь, отредактировать, удалить. Таймлайн будущих ожидаемых событий.

**Вкладка История**

Хронологический лог всего что произошло. Фильтры по типам событий, участникам, местам. Поиск по тексту. Возможность раскрыть событие в полное описание.

**Вкладка Дневник**

Автоматический дневник от лица ГГ. Записи появляются после важных событий. Стиль меняется с возрастом. Игрок может добавлять свои записи.

**Вкладка Прогрессия**

Статы, навыки, черты ГГ. Прогресс-бары. История изменений. Кастомные навыки — редактор.

**Вкладка Инвентарь**

Если в сеттинге есть вещи — список. Деньги. Недвижимость. Питомцы. Важные реликвии.

**Вкладка Система**

Для ГГ с Системой — отдельный интерфейс в стиле RPG-интерфейса персонажа. Задания, достижения, статы в формате который Система присваивает.

**Вкладка Память**

Трёхуровневая. Недавнее (горячая), важное (тёплая), далёкое (холодная). Рефлексии. Ключевые моменты как "фотографии". Прошлая жизнь если есть.

**Вкладка Настройки**

Режим игры. Настройки ИИ (провайдер, модель, лимиты). Настройки темпа. Визуальная тема. Экспорт/импорт мира.

**Панель ИИ**

Плавающая или постоянная панель со статистикой использования ИИ. Токены за сессию, за всё время. Кнопка "написать главу" в режиме хроники. Кнопка "описать момент подробно".

**Быстрые действия**

Всегда доступны: продвинуть время, попросить сцену, переключить режим, сохранить, медитировать (рефлексия), принять решение.

## 11. Стартовый сценарий "Альтер и Харуто"

**Настройка мира**

Жанр — магический реализм в современности. Правила — реинкарнация возможна с сохранением памяти. Магия существует но не у всех. Антропоморфы существуют как меньшинство. Современность, старт 2000 год, детальный период — 2000-2050+.

**Предшествующие события (пре-симуляция)**

История мира с 1900 года до 2000. В основном совпадает с реальностью, но с вкраплениями — первые задокументированные случаи магии в начале XX века, появление антропоморфов как явления в 1960-х, современное общество научилось с этим жить. Базовые ксенофобия и принятие — настраиваемо.

Предки Альтера и Харуто — линия снежных барсов в роду матери или отца, редкая генетическая особенность. Несколько поколений назад были обычными людьми, потом проявилось.

**Пролог — прошлая жизнь (режим книга)**

Отдельная серия глав. Короткая арка в ~5-7 глав:

Глава 1. Обычный вечер, Альтер и Харуто, женатые несколько лет. Детали их любви, привычки, маленькие радости. Просто чтобы привязать читателя.

Глава 2. Авария. Больница. Ожидание.

Глава 3. Операция Харуто. Альтер в коридоре. Память приходит обрывками из прошлого — их знакомство, свадьба.

Глава 4. Смерть Харуто. Осознание.

Глава 5. Похороны. Выгорание Альтера.

Глава 6. Последние дни. Угасание здоровья.

Глава 7. Смерть Альтера.

Все главы генерируются ИИ с очень точными инструкциями по темпу и эмоциональной кривой. Это эталонный кусок для проверки качества движка.

**Возвращение**

Короткая промежуточная сцена — пустота, свет, знакомые голоса, возвращение ощущений.

**Рождение**

Глава рождения. Шок родителей и медперсонала — два младенца-снежных барса, здоровых. Решение оставить, любить, разобраться. Альтер — внутри младенческого тела с полной памятью взрослого человека.

**Имянаречение**

Ключевая сцена через несколько дней. Родители долго выбирают имена. Альтер слышит "Альтер" — ступор, это имя он сам себе выбрал в прошлой жизни. Потом "Харуто" — нокаут. Он не понимает как это возможно. Внутри — слёзы младенца.

**Годы ожидания**

Годы 0-3 проходят в режиме хроники с выборочными сценами. Альтер учится существовать в маленьком теле. Наблюдает за Харуто — младшим братом без памяти. Учится любить его в новом формате. Родители замечают что близнецы очень привязаны — особенно Альтер к Харуто. Первые проявления магии у Альтера, очень слабые, он скрывает.

**Разблокировка (3 года)**

Ключевая сцена. Харуто вспоминает. Это происходит в какой-то момент — может быть спровоцировано (Альтер решается показать ему что-то из прошлого), может спонтанно. Детское тело, взрослая травма смерти, осознание. Первая сцена где они встречаются заново — уже зная.

**Детство с секретом**

Годы 3-18. Братья растут вместе. На людях — близнецы. Наедине — что-то большее, что они не могут пока определить. Как прожить это. Родители начинают подозревать что дети странные — не только из-за вида. Появляется магия у обоих. Альтер создаёт Систему. Знакомство с другими детьми, школа, социализация в мире где они меньшинство.

**Юность и выбор пути**

18+. Отделение от родителей. Независимость. Решение Альтера пройти тем же путём — но теперь с силами. Это разворачивается в основную игру.

**Ключевые якоря сценария**

Рождение (2000). Имянаречение. Первая магия Альтера. Разблокировка памяти Харуто. Первый серьёзный кризис отношений "братья/супруги". Создание Системы. Осознание масштаба сил Альтера. Подготовка к повторению судьбы. Дата-аналог аварии. Развязка — на усмотрение игрока.

**Что нужно прописать заранее**

Профиль Альтера со всеми полями, including previousLife.

Профиль Харуто с memoryLocked до 3 лет.

Родителей, бабушек-дедушек, мир.

Серию из 7 глав пролога как эталонный текст для проверки ИИ.

Скрипт разблокировки памяти как особый тип события.

Правила для Системы — тон, характер, банк реплик.

## 13. Риски и решения

**Риск: ИИ выбивается из характера**

Решение: жёсткие структурированные промпты с контекстом персонажа, темплейты, валидация ответов, возврат на перегенерацию если сильно отклонился.

**Риск: расход токенов неподъёмный**

Решение: процедурная генерация для 70% текста, гибридный режим, режим хроники, лимиты, локальные модели как опция.

**Риск: игроку скучно без целей**

Решение: система якорей заставляет мир двигаться, процедурные события обеспечивают постоянный поток, прогрессия даёт короткие петли удовлетворения, в самой истории должна быть драма.

**Риск: слишком сложный UI**

Решение: поэтапное раскрытие фич, туториал в стартовом сценарии, режимы (новичок/эксперт), большая часть систем работает автоматически в фоне.

**Риск: баги в симуляции создают абсурд**

Решение: валидаторы состояния после каждого тика, логи изменений, возможность откатить на N тиков назад, sanity-check перед отдачей ИИ.

**Риск: мой собственный прогресс замедляется**

Решение: каждый этап даёт законченный кусок, можно показывать друзьям, получать мотивацию. Двигаемся маленькими итерациями.

**Риск: сюжетные якоря игрока плохо стыкуются с симуляцией**

Решение: якоря — это "мягкие" пожелания которые движок старается реализовать, не жёсткие команды. Если условия не сложились — движок подсказывает игроку скорректировать.

**Риск: русский язык кривой (склонения)**

Решение: использовать проверенные библиотеки, тестировать на большой выборке, банк исключений для сложных случаев, для имён персонажей хранить все формы вручную.
